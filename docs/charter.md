## 1. 存在理由(Why)

長さ・重さ・温度をコマンド一発で変換したい開発者のための、Node.js 製の小さな CLI ツールである。
ブラウザで検索する代わりに、ターミナルから離れず `conv 100 km mi` のように即座に変換できる。

## 2. やらないこと(NOT リスト)

- 長さ・重さ・温度以外の単位カテゴリ(通貨・面積・体積等)は扱わない
- 対話型(REPL)・GUI・Web API は提供しない(単発の CLI 実行のみ)
- 設定ファイル・プラグイン機構は持たない(単位表はコード直書き。増やす時はコード変更)
- 秘書系リポ(`~/secretary`・`~/secretary-dev`・devbase)とは無関係の独立 public npm パッケージ。
  Discord 運用外(standalone)であり、devbase の配車(relay-projects.tsv)対象にもしない

## 3. 選定した構造(Core Architecture)

- 構造: **レイヤード(最軽量)**(入口→ロジック→データの一方向依存)
- 選定 ADR: `docs/decisions/ADR-001-layered-structure.md`
- 現構造との差分: 実装済みの3ファイル(`bin/conv.js`→`src/convert.js`→`src/units.js`)は
  既にこの構造どおりの一方向依存になっている。リファクタは不要(ADR-001)

## 4. 使ってよいパターンと用途(共有語彙)

該当なし(3ファイル・単一責務の CLI にパターンを当てはめるほどの複雑さが無い。過剰装備を避ける)。

## 5. 境界づけられたコンテキスト(該当する場合)

該当なし(モジュラーモノリスではない。機能領域は「単位変換」の一つのみ)。

## 6. 検収の合格基準(Governance)

- 品質ゲート: `devbase/verification/quality-gates.md` の G1〜G9 に従う
- 構造検収(G8): ADR-001 帰結どおり、依存規律(入口/ロジック/データの一方向)は**対象外**
  (`.dependency-cruiser.cjs` 未導入。理由=3ファイル規模で目視・grep で足りるため。ファイル数が
  増えたら導入する)
- 逸脱したくなったら: 先に ADR 起票 → 憲章改定 → 検収ルール更新 → 実装(黙って緩めない)

## 7. リスク・夜も眠れない不安(Fears)

- **単位換算係数の誤り**: `src/units.js` の定数を間違えると全変換が静かに狂う。
  `test/convert.test.js` の実測値アサーションが唯一の歯止め
- **public リポゆえの秘密漏洩**: CI の gitleaks(G9)が唯一の機械の歯止め。手動での `.env` 等の
  混入は防げない

## 8. 改正手続き

- 憲章の変更は ADR 起票+この文書の版を更新。履歴節に一行残す。
- 憲章と実装が食い違ったら**憲章が正**(実装を直すか、先に憲章を改定する)。
